# 身份信息管理平台 项目文档

> 版本：v1.0.0　|　文档日期：2026-08-25　|　适用代码：`infocard-id-card-manager`

---

## 1. 项目概述

「身份信息管理平台」是一套面向个人身份档案的管理系统，围绕 `fj_id_card` 身份数据表提供**档案管理、关联登记查询、数据可视化看板**三大能力。

- **档案管理**：人员的姓名、身份证号、手机号、关系、备注等字段的增删改查，身份证号自动推导户籍地区、出生日期、性别等派生信息。
- **关联登记查询**：接入 `cdsgus` 登记表，可按身份证号查询该人员的多条历史登记信息（地址、学历、单位、联系方式等），并标记"是否有记录"。
- **数据看板**：基于人员与手机信息做多维聚合分析（性别、关系、姓氏、出生年份/月份、年龄/年龄阶段、星座、户籍地区分布、手机归属地/运营商），支持全局筛选（是否记录、记录年份）与图表点击下钻查看人员明细。
- **权限体系**：登录认证 + 基于角色的访问控制（RBAC），人员/看板/系统管理按权限分级可见。

### 1.1 技术栈

| 层次 | 技术 | 说明 |
| --- | --- | --- |
| 前端 | 原生 HTML / CSS / JavaScript | 无框架的单页应用（多视图切换），模块化脚本按职责拆分 |
| 图表 | ECharts 5.5.0（CDN） | 柱状图、环形图、折线图、中国省市区地图 |
| 后端 | Node.js + Express 4.19 | 提供 REST API 与静态资源托管 |
| 数据库 | MySQL（mysql2 连接池） | 业务表 `fj_id_card` 及关联表；连接失败自动降级为内存演示数据 |
| 认证 | 自研 Token 会话 + RBAC | Token 内存会话（24h），用户/角色/权限持久化到 `auth-data.json` |

## 3. 产品设计说明

### 3.1 整体流程

```
用户访问 login.html ──登录──▶ 写入 Token 并跳转 index.html
   ├─ auth.js 校验会话（GET /api/auth/me）拉取用户/权限
   ├─ 按权限渲染左侧导航（无权限则进入"无权限"页）
   └─ 默认进入「数据看板」（无看板权限则回退「人员列表」或首个可用页面）
```

### 3.2 功能模块

#### 3.2.1 登录认证

- 极简卡片式登录页，表单校验（用户名/密码非空），错误提示内联展示。
- 默认账号：`admin / admin123`（首次启动自动种子创建）。
- 已登录用户访问登录页会自动跳转主应用。
- 会话有效期 24 小时（内存 Token），重启服务后需重新登录。

#### 3.2.2 人员列表（管理）

- **字段**：姓名、性别、身份证号、出生日期、户籍地区、手机号、关系、是否有记录、操作。
- **搜索**：按 姓名 / 身份证号 / 手机号 关键字模糊匹配（服务端 LIKE）。
- **关系筛选**：Tab 式标签联动（内置 + 自定义关系，按名称升序）。
- **分页**：服务端分页，每页 10/20/50/100 可选；空手机号显示「—」保持行高一致。
- **新增/编辑**：右侧抽屉表单；输入身份证号实时派生「户籍 / 出生 / 性别」；身份证号、手机号（非空）全局唯一性校验（应用层）。
- **自定义关系**：浏览器 localStorage 保存，最多 6 个；自定义关系在数据库中以负整数编码（-1、-2…），避免与内置 0-5 冲突；新增时自动将中文括号统一为英文括号。
- **详情**：弹窗展示人员信息 + 三表关联推导（户籍、年龄、年龄阶段、星座、手机归属地/运营商）+ `cdsgus` 登记记录列表。
- **删除**：二次确认。

#### 3.2.3 数据看板（总览）

看板分三个 Tab：

**① 人员信息**
- 统计卡：人员总数、已记录、未记录（含图标配色，可点击下钻明细）。
- 图表：性别占比（环形）、关系占比（环形）、姓氏分析（横向条形 Top10）、出生年份（折线 Top3 高亮）、年龄（折线 Top3 高亮）、出生月份（柱状）、星座（柱状，按星座开始日期排序）、年龄阶段（柱状，固定阶段顺序）。
- 图表均为可点击下钻：点击任一扇区/柱/点，打开对应人员明细弹窗（带维度过滤条件）。

**② 手机信息**
- 统计卡：人员总数、已记录手机号、待补手机号。
- 图表：手机归属地（柱状）、手机运营商（环形），均可点击下钻。

**③ 地区分布**
- 全国地图（省人数着色），点击省 → 省地图（市）→ 市地图（区）逐级下钻；右侧对应层级人数排名条，地图与排名条悬停联动高亮。
- 顶部面包屑支持「返回全国 / 返回省」。
- 区级支持点击弹窗查看该区人员明细。

**全局筛选（作用于整个看板）**
- 是否记录：全部 / 是 / 否。
- 记录年份：选择「是否记录 = 是」时启用，下拉直接展示有实际记录的年份（避免闪现完整年份列表）；年份筛选基于 `cdsgus` 表「任一记录年份匹配即命中」的语义（EXISTS 子查询）。

**明细弹窗**
- 点击统计卡 / 图表 / 地图区后弹出，分页展示对应人员列表（姓名、性别、身份证号、手机号、出生日期、户籍省市区、关系、是否有记录）；默认每页 100 条。

#### 3.2.4 系统管理（系统）

- **用户管理**：用户增删改、启用/禁用、分配角色（可多角色）；内置 `admin` 账号不可删除、不可禁用。
- **角色管理**：角色增删改、权限勾选、启用/禁用；内置「超级管理员」角色（`admin`）拥有全部权限（`*`），不可删除/禁用/修改，不做数据过滤。

### 3.3 权限设计（RBAC）

- **权限点**（共 7 项，供角色勾选）：

| 权限 Key | 名称 | 分组 |
| --- | --- | --- |
| `idcard:list` | 人员列表 | 业务 |
| `idcard:edit` | 人员列表·维护 | 业务 |
| `dashboard:view` | 数据看板 | 业务 |
| `system:user:view` | 用户管理·查看 | 系统 |
| `system:user:edit` | 用户管理·维护 | 系统 |
| `system:role:view` | 角色管理·查看 | 系统 |
| `system:role:edit` | 角色管理·维护 | 系统 |

- **规则**：
  1. 权限**只通过角色授予用户**，禁止对用户直接授权。
  2. 一个用户可绑定多个角色，权限取**并集**。
  3. 角色可启停；角色被禁用后，其下所有用户立即失去该角色权限。
  4. 内置 `admin` 超级管理员：拥有 `*`（全部权限），不可删除、禁用、修改。
  5. 除登录外所有 `/api` 均需登录；业务接口再按 `requirePerm` 校验权限；无权限返回 403，未登录返回 401（前端跳登录页）。
  6. 菜单/按钮按权限显隐：「新增身份」按钮仅 `idcard:edit` 可见；导航项按对应 `view` 权限显隐；空分组自动隐藏。

### 3.4 关系体系

| 值 | 名称 | 类型 |
| --- | --- | --- |
| 0 | 亲属 | 内置 |
| 1 | 朋友 | 内置 |
| 2 | 同事(瑞联) | 内置 |
| 3 | 同事(优品) | 内置 |
| 4 | 同事(大自然) | 内置 |
| 5 | 同事(财税) | 内置 |
| null | 其他 | 内置 |
| -1, -2, … | 自定义关系（存于 localStorage，最多 6 个） | 自定义 |

> 说明：自定义关系采用**负整数**编码，避免与内置 0-5 冲突；关系标签统一使用英文括号。

### 3.5 关键交互约定

- 看板图表/统计卡均可点击下钻明细，鼠标悬停高亮。
- 地区地图隐藏南海诸岛（南沙群岛），全国图 `zoom: 1.2` 保证省份名称清晰；省份标签自动避让重叠（`labelLayout.hideOverlap`），有数据的省显示「名称+人数」两行。
- 环形图占比内嵌于扇区（深色文字），不足 6% 的扇区不显示文字以避免压盖；图例在底部完整展示「名称 + 人数 + 占比」，超宽自动横向滚动。
- 前端 fetch 统一注入 Token；401 自动清 Token 并跳转登录页；数据模式徽标（MySQL / 演示）在顶栏展示。

## 4. 代码说明

### 4.1 后端

#### 4.1.1 `server/index.js`（服务入口）

- 装配顺序：`cors` → `express.json()` → 静态资源（`public/`、`maps/`）→ `/api/auth`（公开）→ `/api` 全局 `requireAuth` → `/api/system`（RBAC）→ 业务路由 → 统一错误处理。
- **路由清单**

| 方法 | 路径 | 权限 | 说明 |
| --- | --- | --- | --- |
| POST | `/api/auth/login` | 公开 | 登录，返回 token 与用户信息 |
| GET | `/api/auth/me` | 登录 | 当前会话用户、角色、权限 |
| POST | `/api/auth/logout` | 登录 | 登出 |
| POST | `/api/auth/password` | 登录 | 修改当前用户密码（原密码校验） |
| GET | `/api/system/perms` | `system:role:view` | 权限清单 |
| GET/POST | `/api/system/roles` | view/edit | 角色列表 / 新增 |
| PUT | `/api/system/roles/:id` | `system:role:edit` | 修改角色（名称/状态/备注/权限） |
| PUT | `/api/system/roles/:id/status` | `system:role:edit` | 角色启用/禁用 |
| DELETE | `/api/system/roles/:id` | `system:role:edit` | 删除角色（被引用时禁止） |
| GET/POST | `/api/system/users` | user:view/edit | 用户列表 / 新增 |
| PUT | `/api/system/users/:id` | `system:user:edit` | 修改用户（昵称/状态/密码/角色） |
| DELETE | `/api/system/users/:id` | `system:user:edit` | 删除用户（内置 admin 及当前登录号禁止） |
| GET | `/api/id-cards` | `idcard:list` | 人员分页列表（q/relation/nomobile/page/pageSize） |
| GET | `/api/id-cards/stats` | `idcard:list` | 统计（总数/无手机号/按关系） |
| GET | `/api/id-cards/:id` | `idcard:list` | 单条档案 |
| GET | `/api/id-cards/:id/detail` | `idcard:list` | 详情 + cdsgus 登记列表 |
| POST | `/api/id-cards` | `idcard:edit` | 新增档案 |
| PUT | `/api/id-cards/:id` | `idcard:edit` | 修改档案（部分字段） |
| DELETE | `/api/id-cards/:id` | `idcard:edit` | 删除档案 |
| GET | `/api/dashboard/stats` | `dashboard:view` | 看板聚合统计（person/mobile/regYears） |
| GET | `/api/dashboard/region` | `dashboard:view` | 地区下钻（province/city/district） |
| GET | `/api/dashboard/people` | `dashboard:view` | 明细分页（地区/维度过滤） |

- **校验（validate）**：姓名必填（≤20 字）、身份证号格式（15/18 位，走 `parseIdCard`）、手机号格式（11 位 1 开头，可空）、关系整数、备注 ≤500 字；新增/编辑共享，编辑支持部分字段。
- **看板过滤参数解析**：
  - `parseDashScope(qs)`：全局筛选 `hasRecord`（all/yes/no）与 `regYear`（4 位年份），白名单校验。
  - `parseDashFilters(qs)`：图表点击下钻维度（gender/surname/birthYear/birthMonth/constellation/age/ageStage/relation/mobileProvince/carrier/hasRec/hasMob），逐项正则/白名单校验，防注入。
- **启动**：`initMysql()` + `testConnection()` 探测；连接成功用 MySQL（`fj_id_card` 表），失败降级 demo 模式（内存 seed-demo.json），口径回显在顶栏徽标。

#### 4.1.2 `server/db.js`（数据访问层）

- `.env` 加载（`DB_HOST/DB_PORT/DB_USER/DB_PASSWORD/DB_NAME`，仅填充未设置的环境变量）。
- 连接池 `mysql2/promise`，`namedPlaceholders` 开启；`initMysql` / `testConnection` 失败置 `mysqlAvailable=false`。
- **`enrich(row)`**：统一输出前端字段（id、name、card_no、mobile、relation、relation_label、remark、region_code/name、reg_province/city/district、birth、gender_code/name、card_len 等）；字段缺失时用身份证解析结果兜底。
- **`markHasRecord(rows)`**：按身份证号批量（每批 ≤500）查 `cdsgus.CtFId`，标记 `hasRecord`。
- **列表查询**：MySQL 分支使用 `LEFT JOIN fj_admin_region` 补全省市区；条件（q 模糊 / nomobile / relation）动态拼接；COUNT + LIMIT 分页。演示分支在内存过滤分页。
- **唯一性校验**：`findByCard` / `findByMobile`（应用层，因库内历史存在重复数据），新增与修改（排除自身）均校验。
- **`personDetail(id)`**：单条 SQL 通过 4 表 LEFT JOIN（`fj_admin_region` 户籍、`fj_constellation` 星座、`fj_mobile_segment` 手机归属/运营商）推导关联字段；再查 `cdsgus` 登记列表。
- **看板聚合（重点：千万级优化约定）**——详见 4.3。
- **`dashboardPeople`**：明细分页；`codeExpr` 按 level/parent 生成地区条件（省=前2位、市=前4位、区=6位精确或4位市码范围）；`dashboardFilterClause(filters)` 白名单拼接维度条件；结果 `enrich` + `markHasRecord`。

#### 4.1.3 `server/idcard.js`（身份证解析）

- `parseIdCard(cardNo)`：
  - 18 位（`^\d{17}[\dX]$`）：出生日期取 6~14 位、性别取第 17 位奇偶（1 男 / 0 女）、地区码取前 6 位。
  - 15 位（`^\d{15}$`）：出生日期前缀 `19`，性别取第 15 位奇偶。
  - 不合法返回 `invalid: true`。
- `regionName(code)`：内置 `REGION_MAP` 省/市映射，6 位码优先精确匹配、否则回退省份。
- `RELATIONS` + `relationLabel()`：关系值与名称的字典映射（与前端 `app.js` 保持一致，统一英文括号）。

#### 4.1.4 `server/auth.js`（认证与 RBAC 核心）

- 权限清单 `PERMISSIONS`（7 项）；`ALL_PERM='*'`。
- 持久化：`auth-data.json`（users / roles / userRoles）；结构不完整或首次运行自动 `seed()`（创建 admin 用户 + 超级管理员角色）。
- 密码：`scryptSync` 加盐哈希，`setPassword` 换盐重哈希。
- **`permsForUser(userId)`**：取该用户所有启用角色，权限并入 Set；命中 `isAdmin` 角色直接返回 `['*']`。
- **`requireAuth`**：解析 `Bearer token` → 校验有效期/用户存在/未禁用 → 注入 `req.auth`（含 perms、isAdmin、roles）。
- **`requirePerm(perm)`**：admin 自动放行；否则校验 `perms.includes(perm)`，失败返回 403。
- Token：`crypto.randomBytes(24)` 随机串，内存 Map，24 小时过期。
- 保护规则：内置 admin 角色不可删改禁；内置 admin 账号不可删禁；删除角色需无用户引用；`setUserRoles` 支持多角色并集。

#### 4.1.5 `server/rbac.js`（认证与系统管理路由）

- 登录：校验用户名/密码/启用状态，签发 Token，返回用户信息与权限。
- 修改密码：校验原密码、新密码 6-32 位。
- 角色：新增（roleKey 格式校验 + 唯一）、修改、启停、删除（内置 admin 角色与仍被引用的角色禁止）。
- 用户：新增（用户名格式/唯一 + 密码 ≥6 位 + 可选角色）、修改（昵称/状态/密码/角色）、删除（内置 admin 与当前登录账号禁止）。

### 4.2 前端

#### 4.2.1 `public/auth.js`（会话与引导）

- **fetch 拦截**：包装 `window.fetch`，自动附加 `Authorization: Bearer <token>`；响应 401（非登录接口）清 Token 并跳 `login.html`。
- **`auth.ensure()`**：读 Token → `GET /api/auth/me` 拉取用户/角色/权限 → 写入全局 `state`。
- **视图定义 `VIEWS`**：dashboard / list / users / roles，各含 nav 元素、view 元素、权限点、标题、面包屑。
- **`switchView(key)`**：隐藏其它视图、高亮导航、更新页标题与面包屑、广播 `app:view` 事件、触发 `APP_VIEW.notify(key)`（供 dashboard/sys 注册加载钩子）。
- **默认页**：优先数据看板，其次人员列表，再回退首个有权限视图；均无权限显示「无权限」页。
- **导航装配**：按权限显隐菜单项，隐藏空分组；「新增身份」按钮按 `idcard:edit` 显隐。
- **Sidebar 折叠**：状态存 localStorage（`fj_sidebar_collapsed`），两个触发按钮（侧栏内 + 顶栏）。
- **右上角用户菜单**：头像/昵称/角色展示；下拉含「修改密码」（`POST /api/auth/password`，前端校验 6-32 位与两次一致）与「退出登录」。

#### 4.2.2 `public/app.js`（人员列表）

- API 封装：list/create/update/remove/detail/stats。
- 关系体系：`BASE_RELATIONS` 内置 7 项；自定义关系存 `localStorage`（key `fj_id_card.custom_relations`，上限 6）；`relationLabel`/`relationIsCustom` 辅助；关系值 `null` 视为「其他」。
- 状态 `state`：page、pageSize、total、rows、q（搜索）、filter（关系）等。
- 列表渲染：固定行高 56px；空手机号显示「—」；关系标签按值着色（自定义关系使用 `tag-custom` 样式）。
- 筛选：关系 Chip 按名称升序排列；与搜索、分页参数一并提交服务端。
- 抽屉表单：新增/编辑共用，打开时**全量重置**各字段；身份证号输入实时派生户籍/出生/性别；提交前客户端校验 + 服务端 422 错误提示回显；编辑模式预填数据。
- 自定义关系弹窗：名称输入（自动转英文括号）、去重校验、保存后刷新关系选项。
- 详情弹窗：拉取 `/detail`，展示派生字段与 cdsgus 登记列表。

#### 4.2.3 `public/dashboard.js`（数据看板）

- **实例管理**：`state.echarts` 以元素 id（不带 `#`）为 key 存取实例；`getChart()` 先查旧实例是否已 dispose 复用，否则清空容器重建；渲染前 `drawLoading()` 统一 dispose + 显示「加载中…」，避免切筛选后旧图表残留。

- **统计卡**：`renderStatCard` 组合「彩色图标 + 标签 + 数值」；`bindStatClicks` 点击打开明细（带 filters）。

### 4.3 看板聚合 SQL（优化要点）

针对 `fj_id_card`、`cdsgus` 千万级数据量的约定：

| 关注点 | 做法 |
| --- | --- |
| 记录年份筛选 | 用 `EXISTS(SELECT 1 FROM cdsgus d WHERE d.ctfid=f.card_no AND LEFT(d.Version,4)=? )` 命中「任一记录匹配年份」，而非 `MIN(LEFT(Version,4))`（会漏掉多记录人员） |
| 是否记录 | `EXISTS` / `NOT EXISTS` 关联 `cdsgus`，不走全表 COUNT 对比 |
| 地区聚合 | 按身份证前 6 位 `region_code` 聚合：省用前 2 位、市用前 4 位、区用全 6 位，不采用"补零正则"易错方案 |
| 维度过滤 | `dashboardFilterClause()` 对全部字符串值做 `escVal()` 转义 + 正则/白名单校验（关系 `^-?\d+$`、年份 `^\d{4}$`、姓氏单字、年龄阶段白名单等） |
| 分区查询 | 9+3 项聚合使用 `Promise.all` 并行查询；分页 LIMIT/OFFSET 服务端完成 |

### 4.4 数据库表依赖

| 表名 | 说明 | 关键字段 |
| --- | --- | --- |
| `fj_id_card` | 身份档案主表 | id、name、card_no、mobile、relation、remark、region_code、birth_date_str、birth_mmdd、gender_code、card_len |
| `cdsgus` | 登记记录表 | CtFId（身份证号，关联键）、Name、Gender、Birthday、Address、Company、EMail、Mobile、Version（登记年份）等 |
| `fj_admin_region` | 行政区划表 | region_code、province、city、district |
| `fj_constellation` | 星座起止表 | name、start_mmdd、end_mmdd |
| `fj_mobile_segment` | 手机号段归属表 | segment（前 7 位）、province、city、carrier、carrier_type |

> 连接配置见 `.env`；未接入数据库时服务自动进入 demo 模式（内存加载 `seed-demo.json`），便于离线预览。

## 6. 已知约定与注意事项

- 手机号唯一性采用**应用层**校验（库内历史存在重复数据），数据库层不做唯一约束。
- 自定义关系以负整数存储，筛选/下钻条件 `relation` 需支持 `-?\d+` 与 `null`。
- ECharts 实例必须 `dispose` 后再重建并按元素 id（不带 `#`）存取，防止内存泄漏与"切换筛选后图表空"问题。
- 地区地图「南海诸岛/南沙群岛」已隐藏并裁剪，避免小图放大地图时错位。
- 前端页面硬刷新（Cmd+Shift+R）可绕过浏览器缓存获得最新静态资源。
- `auth-data.json` 会实时持久化用户/角色变更；删除该文件可重置为初始 admin 账号数据。
